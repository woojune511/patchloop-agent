# First-input caller information comparison

The opt-in `--caller-evidence` and `--caller-evidence-hash` preparation arguments
select a different intervention in the shared checkpoint collector. Without them,
the existing mutation-advice comparison is unchanged. Do not combine interventions.

A retains the exact original post-probe/pre-edit input. B adds only
`operator_caller_observation` to the latest public current-state record. Its value
contains the later operator probe's executable template, both trigger modes' raw
observations, unchanged public base and provenance/scope. It contains no repair
recommendation, evaluator information, prior model outcomes or interpreted verdict.
The original mutation advice stays identical in both arms. Native encrypted history,
original tool outputs, offered tools, settings and restored allowances stay exact.

Evidence loading verifies the result file hash, hash-chained operator journal,
completed CAS artifact, probe source/driver hashes, task/runtime/base identities,
pinned environment/dependencies, clean receipts and stdout-to-observation identity.
The manifest binds its entire journal hash and projected supplement hash. Preparation
writes the exact A/B request files and a readable supplement outside the repository.
These are new evidence artifacts; original packets and journals remain immutable.

Delivery occurs only in the first new counted/dispatched input. The canonical
context artifact contains the same explicit operator field, so the ordinary public
projection audit can verify the delivered data. Following turns use ordinary
context construction: no automatic re-injection or durable memory is added. A model
may retain a derived fact through its own continuation or working notes. This tests
initial evidence uptake under that policy, not sustained evidence availability.

Use the shared A1/B1/B2/A2 order, inherited remaining row allowances, fresh total
allocation, zero retries and uncertainty hard stops. Preparation is provider-free;
an existing authorization or unused historical funds never authorize this comparison.
The extra input may affect token counts, cost admission and later output ceilings;
record these as treatment consequences, without equalizing them through another change.

Primary observations are the first action, whether the first patch still conditions
interrupt cleanup on waiting-caller cancellation, and the first registered check
results. Inspect actual patches and public decision/evidence records, not wording
alone. Also report subsequent checks on exact diffs, submission, isolated acceptance
and safety, cost and resource-limited NOT_RUN. Delivery does not prove understanding.
Four continuations of one checkpoint cannot establish general solver improvement,
autonomous diagnosis or default adoption. The operator chose the extra measurement
after observing failures; this is a selected diagnostic, not a held-out evaluation.
