# Boundary-pair panel contract

User requested design and execution of the proposed six-task, two-arm, two-repeat
experiment. New delegated invocation cap USD 48, USD 2 per independent run, exact
C:/Users/geonj/Documents/PatchLoop/.env; gpt-5.4-2026-03-05 xhigh, 25K desired output.
Each run uses 40 model calls, 100 actions, four accepted mutations and 1800 seconds.
Twenty-four sequential runs; no retries, replacement, resume or allowance transfer.
Keep the ordinary one bounded protocol correction, identical in both arms; no SDK
transport retries. Count before dispatch; propagate the loop's stop_remaining flag
to the entire panel. Uncertainty or interrupted control flow stops all remaining runs.

Pydantic v1 and HF v5 are known failures; Fromager v1 and Loguru v3 successful controls;
PDM v2 and pgmpy v1 extend this diagnosis. Extension cases have previous execution
history and are not unseen/held-out tasks. All are public dev-train, official=false.
Each run starts from clean base with no historical agent plan/notes/patch/reasoning.
Order alternates arm first by task and reverses in repetition two; no outcome-based
selection, exclusion or retuning. The common starting point is before any agent work,
not a reused source-inspection checkpoint. It includes effects on evidence selection.

A is the selected Current baseline. B appends only the generic TREATMENT in
diagnostics/boundary_pair_panel.py to existing brief-v1 instructions. Tools, schemas,
checks, mutation limits and submission gates are unchanged. The model contract hashes
the actual instructions; every turn's delivered system prompt must be audited after
collection. No target-specific examples or grading criteria enter agent inputs.

All tasks use newly prepared clean base sources. P/H/F reuse validated public
dependency bundles. L/D/G use the existing
stdlib-only public probe environment; this limitation is visible to the agent and
identical across arms. Registered task checks use their separate task environments.
Environment preparation/image checks are separate from task ability; import/setup
failures are not evidence of an incorrect expected outcome. This evaluates the
procedure with current available tools, not an ideal fully provisioned probe service.
Do not automatically start Docker or pull/build images.

Freeze before collection: requests, task/implementation/runtime hashes, schedule,
prices, caps, treatment and preflight receipt. Delegate ordinary execution unchanged
to dev-head, including isolated evaluation only after submission. Never feed private
evaluator feedback to agents or use it to revise this frozen experiment.

Process rubric, assessed on anonymous public traces before arm/outcome mapping:
0 no concrete relevant pair; 1 a task-grounded changed/preserved pair with explicit
outcomes; 2 source evidence or an executed public test discriminates the proposed
condition (a failed setup is not level 2). Separately record whether contradictory
evidence occurred, whether the agent revised a mistaken condition, and whether final
public code preserves the identified boundary. Keep wrong expectations, unrelated
probes and unexecuted proposals distinct. More checks or prose alone are not benefit.
Same investigator, arm-masked rather than independent blind review; content can reveal B.

Final outcomes: paired acceptance wins/losses/ties by task and repeat; safety separately;
NOT_RUN for no submission, infrastructure separately, all 24 planned slots accounted.
Report cost/time/submission and control regressions. Acceptance is the registered task
package result, not automatically an original benchmark score. Favor further study
only if B has more paired acceptance wins than losses, no safety regression, and
public process evidence supports the proposed mechanism. Small selected sample means
no default adoption/general-rate claim. This tests a procedure bundle; component
ablation only after a useful effect is established.
