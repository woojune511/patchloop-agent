# Failed-check cleanup information comparison

`diagnostics/cleanup_information_checkpoint.py` selects the first failed registered
check after the first repair in a saved single-fork continuation. It binds the
next saved counted/dispatched request, public projection, native history and
remaining allowances. Source journals and artifacts remain immutable.

A receives that original request. B adds only `operator_caller_observation` to
the first current-state message and canonical context. It contains the later
operator's traced and untraced probe programs and raw stdout/stderr for the exact
B1 first candidate. No B2 candidate, deletion experiment, interpreted root-cause
verdict, future agent decision or evaluator information enters the supplement.
Program watchdog exit does not mean fixture cleanup completed.

The shared continuation restores verified inherited references into a fresh CAS
and materializes the one completed mutation with exact pre/post file and diff
hashes. Historical actions/checks are not replayed. Native state, original advice,
tools and remaining budgets stay fixed. Subsequent context is ordinary runtime
construction; observations are not automatically reinjected.

The shared collector freezes A1/B1/B2/A2, exact task/model/credential path, remaining
row cost and a new four-row cap in its manifest. Preparation and scripted rehearsal
use no provider calls. Paid collection requires fresh exact authorization; previous
closed allocations are never reused. Existing count-before-dispatch, zero retries,
uncertainty stop and single-use result directory rules apply.

Measure first repair, registered checks, submission, isolated acceptance/safety,
cost and first-input delivery separately. Resource-limited non-submission is NOT_RUN
for evaluation. This selected checkpoint cannot establish general improvement.
