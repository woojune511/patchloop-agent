# First reproduction checkpoint comparisons

`first_reproduction.description()` is used only while acquiring an original.
It retains the environment facts and the APIs needed to construct and observe an
in-process public call. General helper, replay and repair-stage instructions remain
in their existing descriptions. Parameter schemas, validators, acquisition budgets,
failure/processing judgments and saved-program bytes do not change. Surface v66
records the description change; it is not a new observation contract.

The description profile compares the saved long description (A) with the short one (B).
Both start from the same public pre-dispatch checkpoint, with public messages and
read/search results retained. Historical encrypted reasoning is excluded from both
requests. This is a public reconstruction, not a byte-identical historical resume.
Only `run_probe.description` may differ between the prepared first requests.
Neither arm receives a patch, post-checkpoint response, processing-code hint or
private evaluation data. The old failed response is not the new A observation.

Preserve the checkpoint's model, effort, output/context limits, tool schema,
completion policies and remaining resources. Historical costs stay closed; new
funds equal the remaining allowance, separately in each arm and in a shared ledger.
Preparation/count simulation uses inert providers. Real input counting, credentials,
Docker probes and provider dispatch belong only to explicitly approved collection.

Stop each arm immediately after its first settled original probe result (including
preflight rejection, execution failure or mismatch), explicit stop, or terminal
response failure. The ordinary bounded protocol correction can precede that probe.
No edit, repair loop, submission, public regression or isolated evaluation is part
of this diagnostic. A request rejection is not target execution or reproduction.

Record separately: complete valid tool request, host admission, target entry,
complete capture, declared baseline failure match, desired-value mismatch and
processing evidence. Audit whether selected observations cover the actual public
task; a declared match alone is insufficient. Stop both arms on count, transport,
billing, execution or cleanup uncertainty. Do not retry an uncertain arm.

One A/B pair can identify a useful next intervention on this checkpoint. It cannot
establish a stable causal effect, clean-start success, repair gain or generalization.

The model profile instead keeps the recorded long description in both arms and
compares mini/full snapshot IDs at the same xhigh setting. First requests differ
only in model ID. Symmetrically omit the checkpoint's model-priced completion-cost
forecast; retain public evidence, actual remaining allowance and counters. Host
admission still uses each model's rates, with the model/pricing/envelope identity
bound before the fork is written and historical usage restored without repricing.
Offline admission must verify the same 40K initial and 25K correction ceilings and
tool opportunity at the 60K input bound. The first-settled-probe endpoint is unchanged.
This is a new scoped allocation, not reuse of a closed description-comparison cap.
