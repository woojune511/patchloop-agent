# Original-call path diagnosis and discriminating selected tests

This is a bounded dev-head repair aid. It does not change the task oracle or
original-case completion gate. Provider/output/action/edit/wall limits stay fixed.

## Trigger and sequence

`repair_path.review` derives state from immutable public receipts. It activates
only for an acquired unchanged-base original, a healthy comparable current
refutation with consistent host diagnostic judgment, and measured unobserved
changed Python lines in the last implementation mutation's still-current file.
Test additions cannot become the implementation hypothesis. Unknown line coverage
does not trigger a fabricated no-hit. A helper, old candidate, changed call,
conflicting judgment or different file hash cannot trigger the diagnosis.

The current candidate permits one preparation `read_file`/`search_files` when
offered, one `run_probe` replay of the frozen original, and stop. Repair, checks and
tests wait for the diagnosis. Fresh `call_path` selects a public caller focus and
1–4 watched functions with at most six named fields each. Set `replay_action_id`,
`question`, `python_source` and `purpose` to null; do not supply `call_id` or lines.
The host binds the pending original root and failing call from public receipts.
At least one watch must intersect the refuted mutation's unobserved changed range.
The original program, arguments, expected output and failure declaration stay fixed.

At `needs_path_diagnosis`, the existing run_probe schema requires a non-null
symbolic call_path and restricts question/python_source/replay_action_id/purpose
to null. Its short description covers only this diagnostic selection; helper,
new-original and saved-case creation instructions are absent. The host selects
the mode from the workflow gate before counting/preparing the request. Other
gates retain the ordinary schemas and turn-decision metadata is still attached.

The host resolves unique functions with AST, then compiles public source without
executing it to select up to 32 source lines in each function's own frame. Current
changed lines take priority, then ascending remaining lines. Artificial compiler
locations and nested function bodies are excluded; omitted line counts are explicit.
Selection describes the host compiler's line table, not a guarantee of line events
on every target Python version. Function entry, selected line entry and correctness
remain distinct. Source membership and hashes are bound before durable admission.

Shapes and source membership/function/line ranges are checked before dispatch.
One invalid request may be corrected; two rejected requests exhaust the bounded
opportunity. A rejected request does not become an executed diagnostic. One
dispatched attempt with unknown/incomplete output exhausts execution capacity.
Restarts, another action ID and repeated original replays cannot refill it.
Incompatible fields are returned as exact invalid_fields paths with their required
null/false values. Later replay/case preparation cannot overwrite an existing
preflight error. Existing correction receipts compare the named fields and retain
the same pending case/candidate link; original program/oracle fields are never
silently discarded or changed to admit a request.

## Observation and evidence linkage

The host binds regular tracked public Python source or verified prepared
dependency members, source hashes and function locations. The trusted collector
observes only the selected invocation on its launch thread while the focus frame
is active. Calls before the focus, initialization and control invocations do not
count. It records bounded named simple values, call entry, selected line entry,
return and exception type. Values at a line precede its execution; a recorded
exception may subsequently be caught. No arbitrary expression, object `repr`,
attribute traversal or unrestricted locals capture is exposed.

The collector composes with existing changed-line tracing. Its separate framed
report is removed before ordinary output and host diagnostic judgment parsing.
Timeout, truncation, source/trace drift, absent focus/call, or missing report is
`unknown`; only a complete selected-call/focus observation permits no-hit.
Default reproduction observer programs keep their existing bytes.

Diagnosis completion binds case, candidate, failure, mutation, replay request,
execution identity, exported snapshot and watched file hashes. The result must
still reproduce the same original failure. Current diagnosis state retains a
bounded entry/exit summary and exact action reference across context changes;
omitted events remain explicit. Full receipts remain in the public history.
The next edit requires existing `causal_revision` fields and receives a host-owned
link to the diagnosis. This refutes the previous predicted original-call effect;
it does not prove an alternative mechanism or require every changed line to run.

## Selected tests

`run_tests.comparison` is optional: `original_base` or `before_mutation` with an
implementation `mutation_action_id`. The host reconstructs isolated snapshots
and puts identical selected test bytes on both. It reverses exact incremental
mutations with full diff-hash checks for `before_mutation`, rather than using the
state immediately before a later test addition. Only a registered direct Python
pytest command is supported for comparison; wrappers keep ordinary selections.

Per-test setup/call/teardown records distinguish assertion fail-to-pass,
`PASSED_BOTH`, collection/setup failures, body exceptions and incomplete runs.
The result always retains `requirement_fit=UNVERIFIED` and
`original_requirement_credit=false`. A discriminating test still needs a valid
public requirement and original-call mapping. It cannot retire F0010 merely by
passing, populate required-check credit, or replace original replay.

## Resources and recovery

Minimum completion includes the pending diagnostic once, followed by mutation,
fresh required checks, original replay and finish. Protected capacity separately
includes an optional preparation read and request correction. A read already
reserved to acquire a missing repair anchor or for current repair is counted once.
Optional preparation never inflates the minimum. Model-facing `preparation_available`
means a read/search is actually offered after resource filtering, in both path-state
locations. `preparation_allowance_available` separately retains the unspent durable
slot; blocked reason and required-anchor status explain the difference. Lack of capacity
or incomplete diagnosis returns `VERIFICATION_INCOMPLETE`. Ordinary normal and
protocol-correction output ceilings and monetary accounting are unchanged.

`action_started.diagnosis_request` freezes the root, candidate, canonical request,
source hashes and line-selection policy. Raw `action_id + input_hash` stays bound
to the model's original selection. Recovery reuses the frozen construction, rejects
source drift and never recomputes coordinates. A durable rejected request cannot
turn into a dispatch after interruption. Completed results replay; an uncertain
dispatch does not retry. Legacy requests containing explicit call IDs/lines remain
readable for recovery but are absent from the fresh model schema.

A selected comparison reserves two physical executions and the protected
completion successor before starting. If only one execution fits, the offered
schema permits `comparison: null` and keeps the ordinary selection available.
The model batch already counts its first
action; distinct durable child starts add the second. Restore uses the same
count. Exact finished child CAS receipts are reused. A child start without a
durable result is uncertain and is never redispatched; remaining phases stop.
All generated snapshots, logs and receipts stay outside the repository.

Run `uv run --locked pytest @tests/diagnosis-request.txt --basetemp C:/pt/<unique>`
for core construction/recovery/resource controls, then quick once for integration
and isolated mock evaluation. Use `tests/call-path-repair.txt` when changing the
broader comparison mechanism. See the [construction record](../docs/history/2026-10-26-diagnosis-request.md)
and [original implementation](../docs/history/2026-10-25-callpath-repair.md).
