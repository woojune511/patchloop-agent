# Original-call path diagnosis and discriminating selected tests

This is a bounded dev-head repair aid. It does not change the task oracle or
original-case completion gate. Provider/output/action/edit/wall limits stay fixed.

## Trigger and sequence

Before the first successful edit, `observe_original` is offered after an acquired
unchanged-base original has a consistent failure and a distinct clean diagnostic
control. The small request has `hypothesis` and 1-2 `candidates`, each selecting a
public function and predicting entered/not_entered/returned/raised. The host binds
the original root, failing call and current source; AST-selected parameters and
executable lines are the only watched fields. The full frozen program (including
control) runs unchanged. Tracing spans begin/end of the selected original call,
so an unentered candidate is complete no-hit only if collection itself completed.
Return/exception are trace events, not proof of normal return or escaped exception.

`first_observation` binds hypothesis, selections, source/request/snapshot/execution
identities and observed event predictions. A changed original result, invalid
control/setup, partial trace or uncertainty is insufficient. One real execution
is available; two rejected requests exhaust request correction. Admitted pending
work reserves the same opportunity. Changing names or restarting never refills it.
Direct supported editing remains available: these observations test a premise,
not the repair. The next edit records the observation action/status in its receipt;
after editing the observation is historical and the original must be replayed.

Ordinary repair has a compact public view containing current source anchors,
original observations, explicit unverified intent, last mutation/counterevidence,
checks and real remaining budgets. General plan/note rewriting is not required.
No-tool/incomplete correction starts a fresh compact segment with the same public
evidence; request-field errors identify only the invalid fields. Anchor errors use
the existing typed mutation failure and bounded source read. Audit state remains.

The optional route adds one model call/tool action before the existing minimum
edit/replay/check/finish route. Exploration preserves that slot using the maximum
of existing protected slack and the optional route, not their sum. Cost admission
also keeps it after reads, probes, tests and diagnostic checks. Two-child tests
preserve it in both schema and batch admission, even after edit-retry protection
is consumed. Mandatory correction takes precedence. Direct editing can skip it.
Protocol correction keeps its existing run-global credit/output budget.

`repair_path.review` derives state from immutable public receipts. It activates
only for an acquired unchanged-base original, a healthy comparable current
refutation with the same declared failure, and measured unobserved
changed Python lines in the last implementation mutation's still-current file.
When diagnostic rules exist, their host judgment must remain usable. A null-rule
recorded observation may qualify through its healthy frozen original/current
comparisons and exact invocation/condition identity; this does not create a host
diagnostic judgment or upgrade the model-authored requirement mapping.
Test additions cannot become the implementation hypothesis. Unknown line coverage
does not trigger a fabricated no-hit. A helper, old candidate, changed call,
conflicting judgment or different file hash cannot trigger the diagnosis.

The current candidate permits affordable `read_file`/`search_files` exploration,
one `run_probe` replay of the frozen original, and stop. The model chooses whether
to inspect public callers, callees or related tests, or observe execution now.
Reads run one at a time in this stage and have no separate one-read quota. Every
read still consumes the existing global resources. Repair, checks and test execution
wait for the diagnosis; reading a test does not run it. A trace request supplies
`focus` (origin, path,
function), selecting a public function on the suspected failure path. The host
maps current unobserved changed ranges to their innermost unique Python function
frames and selects their parameter names, up to four watches and six fields each.
Module-level/ambiguous changes or exceeded bounds remain unavailable; the host does
not guess a function or collect unrestricted locals. The host binds the pending
original root from public receipts. When diagnostic rules identify the call, that
call remains fixed. With null rules, the model additionally selects `call_id` from
the complete captured `call_choices`; the host does not guess which is the failure
or control. This mapping stays `model_selected_unverified`, even after tracing.
At least one watch must intersect the refuted mutation's unobserved changed range.
The original program, arguments, expected output and failure declaration stay fixed.

At `needs_path_diagnosis`, run_probe accepts focus, plus call_id only when selection
is offered. Once admitted, that call is fixed for request recovery. Read receipts
retain their action identities; they do not grant new budget. Rejected-request and
execution allowances belong to the candidate/case/failure/mutation, so another
call ID cannot refill them. The original program still runs
all its calls, and the full comparison and identities must remain consistent.
All offered diagnosis tools omit turn_decision, plan and memory annotations, including
the preparation read and stop. Explicit null annotations are rejected too. The parser,
gateway batch validator and attempt card preserve this absence through recovery.
The host selects the mode before count/preparation. Other gates retain ordinary
schemas and annotations. A normal symbolic/explicit saved request remains recoverable.

The host resolves unique functions with AST, then compiles public source without
executing it to select up to 32 source lines in each function's own frame. Current
changed lines take priority, then ascending remaining lines. Artificial compiler
locations and nested function bodies are excluded; omitted line counts are explicit.
Selection describes the host compiler's line table, not a guarantee of line events
on every target Python version. Function entry, selected line entry and correctness
remain distinct. Source membership and hashes are bound before durable admission.

Shapes and source membership/function/line ranges are checked before dispatch.
One invalid request may be corrected; two rejected requests exhaust the bounded
opportunity. A rejected request does not become an executed diagnostic. One
dispatched attempt with unknown/incomplete output exhausts execution capacity.
Restarts, another action ID and repeated original replays cannot refill it.
Incompatible selections are returned as exact invalid_fields paths. Legacy symbolic
requests retain their null/false-field diagnostics. Later replay/case preparation cannot overwrite an existing
preflight error. Existing correction receipts compare the named fields and retain
the same pending case/candidate link; original program/oracle fields are never
silently discarded or changed to admit a request.

## Diagnosis input and correction

The full public audit context stays in external CAS. The model's diagnosis view
keeps the immutable task, original/current call observations and judgments, candidate
patch, host watches, already bounded public source bodies (including observed caller
and test files), observed navigation headers, latest diagnostic or exploration
results, offered tools, correction and remaining resources. General
notes, plan and unrelated repair bookkeeping are absent. It reads no private evidence.
Already registered dependency callers retain their separately bounded, read-only
source/provenance field through diagnosis and repair. They are never merged into
repository edit evidence. This does not register new dependencies in normal runs;
the existing global input token/count limits still apply to the actual request.

For segmented-v1, entering/leaving diagnosis starts a public-evidence segment with
the appropriate system prompt. Diagnosis seeds do not import old reasoning or
note-selected exchanges. Leaving restores general repair context and the saved plan.
No model plan review is recorded during diagnosis. Native continuations are validated
before any boundary, and archived input artifacts remain linked for recovery.

Output-incomplete/no-tool protocol corrections start a fresh compact diagnostic
segment with the same original/candidate evidence. Request-shape errors correct only
the named fields, without this forced boundary; source-binding rejection corrects
focus through the existing rejected-request allowance. Actual unknown/incomplete trace
does not earn another execution or release repair. Repeated no-action output exhausts
the existing protocol allowance and cannot submit. No boundary renews money, output,
model/action, preparation, request-correction or execution limits. Append/window modes
receive the small current view and conditional annotation rule but preserve their
native history; the fresh-segment behavior belongs to segmented-v1.

## Observation and evidence linkage

The host binds regular tracked public Python source or verified prepared
dependency members, source hashes and function locations. Fresh first-observation
and small diagnosis requests cover the selected invocation on its launch
thread, including watches outside focus. Saved requests without `scope` retain
their focus-subtree meaning and raw input identity. Other invocations, threads
and processes remain unmeasured. It records bounded named simple values, call
entry, selected line entry, return and exception type. Values at a line precede its execution; a recorded
exception may subsequently be caught. No arbitrary expression, object `repr`,
attribute traversal or unrestricted locals capture is exposed.

Entry discovery and selected-frame observation have separate 200,000-event
limits. Unselected frames receive no local line tracing unless the trusted
changed-line collector needs it; delegated events do not consume selected-frame
capacity. Counters saturate at limit+1 after a gap. Such coverage, trace/source
drift or an incomplete call stays unknown and cannot establish absence.

The v2 report separates complete coverage from sampled detail. Event counts and
selected line hits continue independently of the 48-record/8,000-value-byte
sample budgets. Function aliases and overlapping focus/watch selections share
physical samples. Equal bounded projections coalesce with occurrence counts;
per-function shares retain the first and recent distinct samples, keeping one
hot function from crowding out later targets. Grouping is not chronological call
pairing, and equal clipped values do not prove equal full values. The 24,000-byte
wire cap can discard detail while retaining counters. `collection` exposes
coverage, retained/omitted/coalesced counts and exhausted budgets with the first
bound target/event/line where available; unselected frame values are not captured.

Only validated complete coverage permits event/line absence. Missing samples
never prove no return or exception: premise predictions use `event_counts`.
Legacy reports without v2 metadata retain their original conservative semantics.
Summaries carry collection limits and event counts into the next repair context.

The collector composes with existing changed-line tracing. Its separate framed
report is removed before ordinary output and host diagnostic judgment parsing.
Timeout, coverage truncation, source/trace drift, absent call, legacy absent focus,
or missing report is `unknown`; only complete scoped coverage permits no-hit.
Default reproduction observer programs keep their existing bytes.

Diagnosis completion binds case, candidate, failure, mutation, replay request,
execution identity, exported snapshot and watched file hashes. The result must
still reproduce the same original failure. Current diagnosis state retains a
bounded entry/exit summary and exact action reference across context changes;
omitted events remain explicit. Full receipts remain in the public history.
Collection completion and original-call effect are separate. `diagnosed` means
complete collection, while `original_effect_status` remains refuted. The bounded
`factual_refutation` retains the unchanged failure, unobserved changes, sampled
exception sites and their exact evidence action/diff. A caught exception or return
event is not proof of where the original failure escaped.

After diagnosis, the compact edit schema adds `repair_prediction`. A source edit
selects a host-numbered function and a changed entered/not_entered/raised/not_raised
event, or target -1 with `original_failure_absent`. An event already true in the
failed observation cannot serve as the changed prediction. `not_raised` requires
entry plus zero exception events. Model prose explains the revised mechanism;
neither that prose nor a valid prediction proves the mechanism or task correctness.

The host attaches diagnosis/mutation/refutation identity and checks the prediction
on the already-required automatic original replay. Function predictions add bounded
whole-call tracing to that replay; no extra model call or probe is scheduled. The raw
replay arguments/action identity stay unchanged. Current source, call, request,
snapshot, execution identity, inputs, binding and environment must match. A removed
function, partial trace or changed invocation gives unverified prediction feedback
while preserving the original replay. Prediction and original-effect results are
reported separately and never supply required-check credit.
Rule-based replays still require a usable host judgment. Null-rule replays use
their healthy frozen comparison and unchanged invocation fingerprint, so a linked
repair prediction can be assessed without inventing a diagnostic judgment.
The model-selected call mapping and semantic correctness remain unverified.

Only host-admitted additive test mutations can carry a prior diagnosis across a
full-diff change. Every incremental mutation receipt must agree, runtime source
must be unchanged, and a fresh current original must reproduce the same captured
failure with identical binding, conditions, image and profile. Configuration,
conftest, initialization or unproven/legacy edits cannot qualify. The reused trace
keeps its historical diff/snapshot and `current_snapshot_trace=false`; it is not a
new trace of the current snapshot. Unknown attempts, consumed request allowances
and charged read history carry forward too. Source changes still need
their own current evidence.

## Selected tests

`run_tests.comparison` is optional: `original_base` or `before_mutation` with an
implementation `mutation_action_id`. The host reconstructs isolated snapshots
and puts identical selected test bytes on both. It reverses exact incremental
mutations with full diff-hash checks for `before_mutation`, rather than using the
state immediately before a later test addition. Comparison supports registered
direct Python pytest and the exact shared public copy wrapper. The latter keeps
its temporary copy, source priority, environment, arguments and exit propagation;
only the child pytest launch gains the reporter. Unrecognized wrappers remain
unsupported rather than silently losing their setup.

Per-test setup/call/teardown records distinguish assertion fail-to-pass,
`PASSED_BOTH`, collection/setup failures, body exceptions and incomplete runs.
The result always retains `requirement_fit=UNVERIFIED` and
`original_requirement_credit=false`. A discriminating test still needs a valid
public requirement and original-call mapping. It cannot retire F0010 merely by
passing, populate required-check credit, or replace original replay.

For one diagnosed implementation, at most one bounded paired selection can use
minimum completion reserves. A test-only edit uses `repair_prediction.kind=test`
and names a registered suite plus the added/extended function or method. The host
checks that this edit actually adds that test and that the suite supports comparison.
It freezes `before_mutation` to the diagnosed source edit. Test addition leaves
source repair unresolved, consumes a normal accepted-edit slot and requires room
for a later source edit. Its next model action is the frozen `run_tests` selection
or stop, without plan/memory annotations. No fresh path diagnosis is required when
the strict historical-reuse conditions above hold.

`PASSED_BOTH` is non-discriminating; malformed or incomplete comparison is
unverified. Both leave original-call requirements unchanged. Starting/completing
the pair does not grant another pair on the same diagnosis. Outside this bounded
diagnosis path, ordinary selected tests retain their existing behavior.

## Resources and recovery

Minimum completion includes the pending diagnostic once, followed by mutation,
fresh required checks, original replay and finish. Extra diagnosis-stage reads
preserve that minimum plus unused diagnostic request correction; an arbitrary
caller/test read is not assumed to supply a missing mutation anchor. Provider
admission also reserves the successor's response roles and pending diagnostic
execution time. With `completion-recovery-v1`, ordinary paths use the same steps
for response/action counts, cost and time. Known-original-failure exploration can
release a speculative later revision if needed; the per-action route reports that
tradeoff while preserving current diagnosis, correction and completion. See
[completion resources](completion-resources.md). Repeated exploration cannot
refill any global limit.
Model-facing `preparation_available` means a read/search is actually offered after
resource filtering, in both path-state locations. The compatibility field
`preparation_allowance_available` describes eligibility while diagnosis is pending,
not an unused one-read ticket. `preparation_action_ids` remains the charged read
history. Blocked reason and required-anchor status explain current availability.
When surplus is exhausted, only the affordable diagnostic or stop is offered.
Lack of completion capacity
or incomplete diagnosis returns `VERIFICATION_INCOMPLETE`. Ordinary normal and
protocol-correction output ceilings and monetary accounting are unchanged.

`action_started.diagnosis_request` freezes the root, candidate, host watch plan,
canonical request, source hashes and line-selection policy. The execution adapter
removes focus and the top-level call_id from its derived replay arguments only;
the selected call remains inside call_path. Raw `action_id + input_hash` stays bound
to the model's original selection. Recovery reuses the frozen construction, rejects
source drift and never recomputes coordinates. A durable rejected request cannot
turn into a dispatch after interruption. Completed results replay; an uncertain
dispatch does not retry. Legacy requests containing full call_path coordinates
remain readable for recovery but are absent from the fresh model schema; a
top-level call_id is offered only when the host has no rule-based mapping.

A selected comparison reserves two physical executions and its completion successor
before starting. Ordinary optional selections use the protected successor; the
single diagnosed comparison may use the minimum successor. Only ordinary selections
can fall back to `comparison: null` when two executions do not fit. A frozen pending
comparison instead returns verification incomplete if it cannot fit.
The model batch already counts its first
action; distinct durable child starts add the second. Restore uses the same
count. Exact finished child CAS receipts are reused. A child start without a
durable result is uncertain and is never redispatched; remaining phases stop.
All generated snapshots, logs and receipts stay outside the repository.
