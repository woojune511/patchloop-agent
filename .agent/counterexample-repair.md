# Public counterexample revision diagnostic

`diagnostics/counterexample_repair.py` prepares one operator-assisted continuation
before finish, with public counterexamples for a saved model candidate. It is not
an ordinary fresh solve, benchmark test change or new production gate.

Use a prepared-request cut in the existing observation fork, preserving settled
historical counts/cost, accepted edits, original-case identity, caller registration
and the current candidate. No finish, terminal or evaluator result enters the prefix.
The unchanged-base-only after-tool-batch path is not used or broadened.

`counterexample_packet.py` verifies the sealed public diagnostic artifacts and raw
captures. The model projection contains the public fixture program, inputs,
expected/measured outcomes and measured/current diff identities. Host paths,
operator diagnosis, private evaluation status and repair instructions are excluded.
The outer request asks for a revision, without supplying an implementation.
Changed diffs mark the original observation historical, requiring new measurement.

The scoped overlay updates canonical context and each actual model request before
normal input counting. Preparation uses finite, network-disabled clients to check
first count/dispatch parity and delivery after a subsequent read response. Existing
tool schemas, original replay, public checks, finish eligibility and evaluation
remain ordinary. A model can stop or submit without repairing; record that outcome.

The diagnosed case partition is frozen: preserve all eleven baseline-correct
cases, including correcting the three candidate regressions. One discrepancy that
already existed on the base is reported separately, not added as a new obligation.
These examples are operator-provided development assistance, not hidden tests.

Reserve one tool action and35 seconds for one final public matrix execution.
The diagnostic fork reduces its ordinary runner limits by those amounts before
writing the new envelope, and binds the reserve in its hash-chained marker.
Historical usage, model/edit/cost limits and evaluation reservation are unchanged;
combined execution must remain inside the original tool/time caps. Zero reserve
keeps prior diagnostic behavior. Ordinary resume contracts are not relaxed.

The final matrix observes the exact settled submitted diff after normal completion
and is not sent back to the model. It is not a check after every edit. The normal
runner still replays the original call after edits. A final matrix is skipped when
there is no settled submission or execution/billing is uncertain. Its entire phase
uses one deadline and at most one dispatch, with image/profile/dependency/program,
output completeness and unchanged-source checks. Failed public cases are valid
FAIL observations; incomplete execution remains unavailable. There is no retry.

Preparation seals the full packet, first actual request, source/configuration,
new exact positive cap, one repeat and remaining resources. Collection requires
that manifest hash and exact fresh cap, clean tracked runtime and diagnostic code,
existing images, immediate counting and zero SDK retries. Prior unused allocations
remain closed. No automatic provider dispatch follows preparation.
