# Evidence/context preparation

Provider-free entry points in diagnostics/evidence_context_design.py: prepare(root),
validate(packet_path). No collector, credential read, token count, model selection,
API request, tool execution or paid authorization. State stays external in CAS and
dev-run-v1. Sources and historical artifacts remain immutable.

Four dev-train checkpoints: HF v5 B2 final; HF v5 B1 final; AnyIO v3 N1B final;
tox-cross-section-empty-substitution v1 TA immediately after the missing-default
probe and before the next response. These span three tasks. The tox case includes
the previous import failure and later candidate-linked reduced execution; later
operator CLI confirmation and all post-cutoff decisions/evaluator outputs are excluded.

Both views are fresh, non-executing public evidence reviews with the same neutral
question. A includes surrounding context; B contains the common evidence core only.
Neither is the original coding-agent request or an actionable finish/repair episode.
All four actual source inputs contain five messages and zero reasoning items. No
encrypted continuation is removed by this comparison; unsupported layouts fail closed.

The common evidence retains the complete public task/check definitions, current
patch and identities, current observed source, check/probe results, external feedback,
registered verification observations and historical public evidence archive. Resolve
source references from delivered material only; do not read new repository source.
Keep archived probe code/questions, exact outputs and action/candidate identities.
Move archived call turn_decision prose to A's context; do not remove actual arguments
or results. Original source/task/check assertions are fallible public evidence, not
new reviewer answers. A also retains original system/tool descriptions and other
current state (plans, notes, budget, completion advice) as quoted data.
Only the seven named CONTEXT_FIELDS move out of current state; all other fields,
including mutation results and mixed evidence/advice records, remain in both views.
This preserves facts conservatively and does not remove every possible framing cue.

Reconstruct the original state from the evidence and extra-state split, restore the
original archive argument objects, compare common evidence hashes, and hash-check
saved source/derived files. Report UTF-8 bytes, not guessed token counts or savings.

Reviewer-only case notes: C1 current operator-observed discrepancy; C2 historical
observation without a delivered exact current rerun; C3 setup failure distinct from
later current lifecycle PASS; C4 current missing-default mismatch in reduced target
execution after import failure. Treat C4's stubs/import bypass as limits; do not claim
whole CLI coverage. Scores, selection labels and these notes never enter the views.

For a future comparison, assess observed status, applicability, candidate currency,
PASS coverage and sufficiency of cited evidence with the same rubric in both views.
Missing evidence permits uncertainty; neither output length nor the word 'resolved'
earns credit. Both views failing would not prove intrinsic inability; both succeeding
would not prove native-loop repair ability. A difference localizes a bundled context
effect, not uniquely history, length, completion advice, or a particular component.
Preparation supplies no fixed live model, repetition count, cap or execution approval.
