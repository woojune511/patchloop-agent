# Request and correction continuity

Fresh `run_probe` schemas match the stage. General probes use null `call_path`;
pending original-call diagnosis uses its focus-only schema. Original acquisition
offers a new `original_requirement` program with non-null question/source and no
replay, symbolic path, judgment correction or helper-case registration fields.
Only reads/searches may batch; other actions remain single. Provider parallel
generation is disabled whenever the offered gate cannot accept a read batch.
Counting and generation use the same setting. Stored turns retain their exact
acquisition-mode validation flag; missing legacy flags do not acquire new rules.

Fresh `bounded-v1` acquisition registrations bind `inspection-then-request-v1`.
Six preparatory actions close reads/search/history, leaving the original request
or stop. They do not release the obligation or spend the two execution slots.
Rejected non-helper requests keep their separate two-request bound. Helpers in
direct/legacy receipts spend preparation; they cannot create an extra allowance.
Preparatory reads reserve one original dispatch and its acquired-case completion
route in model, tool and cost admission. Shared budgets may still release an
unaffordable acquisition, without verification credit. Existing registrations
retain the shared-six rule, and uncertain dispatches remain unverified.

`correction_drafts` retains at most two rejected edit argument objects within
32,000 total canonical UTF-8 argument bytes. It records origin turn/action,
input/arguments hashes and the unchanged diff, labelled unexecuted and unverified.
Whole bodies are retained or explicitly omitted; there is no silent truncation.
The correction journal, gate refresh and compact context carry the same packet.
A changed diff withholds the bodies and labels the packet stale. No action is
automatically retried: the model must return a new single registered action,
subject to the normal schema, exact-anchor, scope and resource checks. Drafts
grant no source, mutation, check or completion credit and no extra retry funding.

Core: `uv run --locked --offline pytest @tests/request-continuity.txt -n 4
--dist loadfile --max-worker-restart 0 --basetemp C:/pt/tmp/<unique>`.
The fixtures cover oversized encrypted continuation, correction and recovery,
same-diff draft bodies, omitted/stale bodies, stage modes and budget boundaries.
They test local mechanics only; actual model progress and F0010 repair need live
evidence. No paid run or evaluator-image preparation is part of local validation.
