## Problem and selected change

The [request audit](2026-10-23-request.md) found that the live model recognized a
literal-quote rejection but repeated identical arguments. Two rejected requests
produced zero original-caller executions; subsequent repair targeted a different
branch from the public failure. The user authorized the first intervention only:
request construction and correction judgement, with shorter local validation.

Baseline: `1348bdc1d99071425e509e780a8f2eb295bef545`. The local protocol is
`C:/pt/request23-local/protocol.json`, registered before implementation in
`runs/run_dev_request23local.jsonl` with content-addressed artifacts. No model,
Docker, evaluator image preparation or paid experiment is included.

Fresh purposes omit `requirement_quote`; the host binds the complete current
public-task hash and exact public issue-content hash. This removes transcription
from the critical request path without weakening the source identity or certifying
issue-to-caller mapping. Existing admitted quote-bearing definitions keep their
canonical identity and executable wrapper on recovery/replay.

Field diagnostics and durable admission receipts distinguish identical arguments,
changed but invalid requests, and a valid correction changing the named error
field. Different decisions/action IDs give no correction credit. Helper substitution,
setup failures and uncertain dispatch remain separate. The receipt is reused after
a crash, without changing `action_id + input_hash` idempotency. Surface v49 records
the changed contract; active schema pins move, frozen comparison-arm pins do not.

Acquisition release, request/attempt caps, edit-time scheduling, cost reservation
and finish rules are unchanged. Corrected means request-valid, not executed or
verified. Whether the model actually uses this path remains an open question.

## Decision and remaining question

Keep the smaller fresh request schema and mechanically grounded correction receipts.
The controls support field validation, actual-argument comparison and recovery;
they do not prove that a model chooses the right caller or repairs more tasks.
Full regression, Linux, live model uptake and task repair improvement remain untested.
The next implementation stage is edit-time use of acquired caller evidence and its
budget path; it is separate from this request-layer change. No paid allocation is
reopened, and current acquisition/completion behavior has not been tightened.
