# Caller invocation comparison qualification

The closed role experiment repeatedly confused a declared original caller with
helper execution. Direct invocation and recorded conditions are now implemented,
but their effect on model behavior is unmeasured. This follow-up makes the
[OFF/ON specification](../../.agent/plans/probe-invocation-comparison.md) executable
without changing architecture, transitions, two references or total resources.

## Controlled implementation

`diagnostics/probe_invocation_control.py` restores the pre-change description,
`record-observation-v1` selection, wrapper and review in A. B retains direct
`call_target` execution. Both select **role A, same-context verification**. Unit
controls compare A against commit `50b91b5`, exercise actual before/after replay,
check scope cleanup and prevent old comparison packets from passing qualification.
The product runtime is unchanged by this diagnostic implementation. Rejected probes
remain attempted actions when no execution payload is returned; they receive no
bound-call or original-scope success credit.

The new public grader separates opportunity, attempts, mechanically bound calls,
faithful original scope, measured pairs, delivery and supported subsequent use.
It preserves final and earlier completion errors separately from report judgments
and native-plus-two-caller acceptance. Missing B metadata cannot automatically
reject a valid legacy alias/constructor in A. A bound call to the wrong helper is
not faithful verification. Same-program comparison requires a failing baseline,
an intervening accepted edit, comparable conditions and both actual receipts;
current validation without a baseline remains useful but is not a measured repair.
Semantic mapping still requires quoted public evidence and explicit review. This
is an audit with provenance checks, not an automatic semantic judge.
Correctly using a limited or failed observation to revise the next check receives
separate limitation-use credit. It cannot certify original-scope verification or
qualify as faithful linkage in the adoption screen; rejecting all such use would
hide an intervention that improves judgment without yet improving repair.

## Offline observations

- Initial inputs differ by 514 UTF-8 bytes (75,679 A / 76,193 B); schemas, prompts,
  masks, task, budgets and original source/receipts agree after derived IDs are
  normalized. Guidance adds 91 tokens with the cached local tokenizer.
- Six common historical verification checkpoints produce A/B inputs with the same
  phase architecture and only the permitted guidance/review differences. The
  largest saved-count anchored upper estimate is 53,818 tokens, below 60,000.
- All 149 saved public inputs and six sealed public judgment audits are replayed.
  Old classifications and legacy execution bytes agree; no historical program or
  model request is executed. The new inventory also exposes missing, summarized,
  stale and restored receipts even when no later action uses them.
- The fixed-input projection itself removes no original source or receipts. One
  input, A3 sequence 250, is close enough to the cap that the new description gives
  a central estimate of 60,003 tokens (upper sensitivity 60,131). Rebuilding that
  checkpoint using the existing size transition yields 29,665 central / 29,793
  upper, and drops **547 source lines and nine read/search receipts**. This is an
  offline sensitivity, not a measured future transition or continuous new rollout.

That possible loss is material. It includes parts of `modpath_from_file_with_callback`,
`check_modpath_has_init`, `file_info_from_modpath`, module/namespace classification,
builder/manager paths and other-function branches. The nine receipts include
registered test-file reads and import helpers. They can support path/setup and
countercondition reasoning; their absence must not be described as harmless merely
because the remaining packet is smaller. Exact file hashes/ranges and receipt IDs
are recorded in the external `input-comparisons.json`. The two-reference limit is
unchanged, and this historical checkpoint selected no optional references.

Local A/B scripts choose a pre-edit baseline, replay it after the edit, preserve
both selected results through the report and final decision, and reach isolated
mock evaluation. A generic original input plus a normal-input control executes
within the existing 8,000-character wrapper and observation/report limits. These
scripted choices demonstrate feasibility, not that a model will choose them.

At the worst allowed 60k input, minimum-output verification probe+report costs
USD 0.091152 within its USD 0.20 reserve. Initial baseline/read/edit/check and the
final completion path retain the existing phase caps and shared ledger. Large
outputs can still consume this headroom; no useful-reasoning guarantee is made.
The [official model/pricing documentation](https://developers.openai.com/api/docs/pricing)
was checked: USD 0.75 input, 0.075 cached input and 4.50 output per million tokens
for the specified mini snapshot. No provider generation or input counting occurred.

## Evidence and decision

The first completed full suite at `5e89502f` had four stale guidance-digest
expectations (5,565 passed, four failed, 20 skipped). A four-surface OFF/ON byte
comparison confirmed that only `run_probe.description` changed, and OFF still
matches every earlier digest. The current expected digests were updated while
keeping all four case identities, exact-byte assertions and historical removal-arm
expectations. The inexpensive entire guidance-contract file now runs in the quick
suite. This changes no runtime behavior, limits or skip conditions. The failed
full XML remains at `C:/pt/probe-invocation53/frozen/full-final.xml`; the diagnostic
proof is `C:/pt/probe-invocation53-work/description-drift.json`.

Preparation diagnostics and initial failures remain under
`C:/pt/probe-invocation53-work`. Final qualification, focused/quick/full XML,
source/environment bindings and `validation.json` belong to
`C:/pt/probe-invocation53/ready`. The final implementation commit is recorded in those
receipts and the immutable `manifest.json`; freeze rejects a different commit,
changed implementation, missing qualification or changed skip set. A missing
manifest means preparation is not complete. No results are borrowed from an old
allocation. Historical reports and the user's existing AGENTS.md edits are preserved.

The packet proposes A3/B3 on Astroid-1333 with the specified model and project
credential file, USD 0.88 per row / USD 5.28 total, serial fixed order. It binds
the separate public-audit seal and at most 12 caller/6 native local assessments.
Paid collection remains **NOT_RUN and unauthorized**. Existing stop rules and
no-retry/no-resume/no-replacement behavior remain in force.

The next question is still whether the model selects and correctly uses this
facility, and whether that changes wrong completion claims and accepted repairs.
The additional possible source displacement is a competing explanation to retain
in that analysis. Offline qualification supports running the bounded comparison;
it does not support adopting the feature as a quality improvement.
