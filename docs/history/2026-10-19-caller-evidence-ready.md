# Saved caller evidence: executable checkpoint preparation

Date: 2026-10-19. Provider-free implementation and preparation; no paid allocation.

The [specification](2026-10-19-caller-evidence-spec.md) asks whether exact public
calling conditions change judgment and repair at the same failed decision. The
user requested an executable comparison, local restoration/oracle checks, full
tests on the final commit and a frozen execution manifest. This work prepares that
diagnostic; it does not adopt a context policy or measure model quality.

The task-neutral saved-base adapter verifies the historical count/dispatch/request,
prefix through the prepared segment, settled usage, empty source diff, public
observations and their original journal receipts. A/B restore the same caller-capable
environment. B receives the existing operator observation only in its first new
counted/dispatched input. Later turns use ordinary context handling. The loader
rejects any modified-base checkpoint instead of importing a future patch or decision.

Connecting the existing restore path exposed an omitted-option defect: the old
request reconstruction did not inherit evaluation reservation, retention selection,
agent policy or probe replay policy. It now restores those envelope-bound settings.
The first-state check normalizes only elapsed solving/total time; changed reserves,
call allowances, plans or other behavior still fail equality. The Astroid envelope
retains its 330-second reserve, 24k retention and two question references.

The serial runner binds twelve continuations, remaining row allowances and new-cost
accounting. It preserves a completed result even if a subsequent due-receipt check
fails, then stops remaining rows. Public audit excludes inherited decisions and
opaque reasoning bytes, verifies first delivery, and must be sealed before opening
new assessments. Human semantic annotations distinguish autonomous acquisition,
supplied/prompted verification, delivery/currency, judgment and material action.
Registered/native acceptance and both public caller cases remain independent axes.

The new comparison assesses native acceptance on the full submitted patch and
caller behavior on its source-only projection. The existing assessor keeps its old
default for closed-study follow-ups. Tests-only submissions still get base caller
assessment; silence/skipped child analysis does not pass. No limits or oracle
conditions were relaxed. Original calibration programs use CRLF and the frozen
input contains LF text: only that newline projection is explicit, with raw program
hashes and first-request hashes preserved.

Evidence root: `C:/pt/ce19ready/`. Preparation records actual-checkpoint scripted
A/B restoration separately from public base/control executions. A missing-initializer
positive repair remains unavailable; synthetic oracle positives test parsing and
lineage, not sensitivity to every valid fix. Local fixture acceptance is not an
autonomous Astroid repair. Exact new provider input counts remain NOT_RUN.

Final-commit `validation/validation.json` binds focused tests, Ruff, full-suite JUnit
and mock isolated evaluation. `packet/manifest.json` binds their hashes plus the
source packet, runtime, implementation, prepared inputs, oracle, rubric, pricing,
native harness and row order. A receipt is authoritative only when its gates pass;
this record does not substitute for a missing or failed final validation.
