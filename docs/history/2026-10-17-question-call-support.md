## Question and decision

The [preceding audit](2026-10-17-question-priority-relevance.md) found a structural
gap: the two explicit ranges preserved the failing callee and a namespace branch,
but omitted the caller's path/source/name decisions and seven lines excluding a
later local name derivation as the cause of an earlier open failure. A manual
exchange fit within 24k; it was not an implemented selector or composed request.

The requested intervention keeps transition rules, the two-reference schema and
all resource limits. It adds a general observed-syntax tier rather than encoding
the saved task's names or line numbers. The decision supported here is to retain
the directly connected observed call context before ordinary recency. This is not
evidence that syntax yields the smallest semantically sufficient context: the
remaining losses below include useful indirect conditions.

The [frozen protocol](../../.agent/plans/question-call-support.md) specified public
saved snapshots, the existing operator declarations, legacy/stale controls, exact
source budgets, displacement review and zero provider/count calls. No subsequent
action or evaluator outcome determined the declarations or selection.

## Implemented contract

`patchloop/dev/question_support.py` operates solely on current observed line text.
For Python, it extracts parseable function fragments with an observed closing
dedent boundary; it never joins unseen gaps or different file versions. Literal
bodies are excluded, including multiline f-string text, while quoted annotations
and defaults do not hide real function headers.

The two admitted citations seed local statements and parameter rebindings, local
assignment/import dependencies, controlling branch headers, exception alternatives,
cleanup, bypass/fallthrough exits and preceding calls used for their effects.
Uniquely named observed immediate callers and targets called within the citations
provide additional argument/return conditions. Terminal-name matching produces a
syntactic candidate, not resolved dynamic dispatch. Expansion is one hop; calls in
the newly added support do not recursively expand. No question-prose classifier,
task/file/symbol-name rule or additional model call is used.

`context.py` retains mutation anchors/postimages first, then the existing explicit
countercheck and primary ranges. It admits the union of inferred support atomically
within the remaining source budget, then runs ordinary selection. An oversized
bundle gets no priority admission; ordinary selection can still retain its lines.
Native delivery, line/version deduplication, exact newline costs and existing
omission reporting are unchanged. No extra reference is persisted or added to the
question. Unsupported languages, incomplete/unparseable scopes and ambiguous
observed names add no corresponding inferred support.

The context identity is now
`observed-mutation-paired-call-support-24000-chars-v3`; the default tool surface is
`sha256:57193859890419b79cb7f4927c37796d044bc4bf7159c51ddf17723849529e26`.
Prompt text, wire schema, two-reference/500-character question bounds, diff-scoped
eligibility, note/concern lifecycle and interpretation labels remain unchanged.
No old hypothesis becomes a fact because its source is selected.
