# Why the rejected reproduction did not recover

Date: 2026-10-23. Follow-up to the [closed live pilot](2026-10-23-oracle-live.md).
Saved public evidence and pure local binding checks only; no live rerun or runtime edit.

## Question and evidence

The pilot delivered an unverified patch that failed both independent acceptance and
the frozen missing-initializer public condition. The immediate question is whether
the repeated invalid request reflects missing error feedback, a failed argument
correction, or an unavoidable reproduction-program failure.

The model's public decision on call 3 explicitly identified the quote rejection and
said it would retry with exact quoted text. Nevertheless, every tool argument in the
two `action_started` records is equal, including purpose, question and program. Only
the surrounding action identity/decision changed. Thus the record supports a mismatch
between the claimed correction and the submitted arguments. It does not support a
claim that the model never received or recognized the primary error. The separate
working-note rejection is not an adequate explanation for this response.

The invalid quote joined the failure description to a paraphrase of desired behavior
and doubled path separators. `reproduction.bind` requires a literal substring of the
public title or description. The host correctly rejected the provided string.

## How the remaining failure followed

1. `original_obligation.review` releases acquisition after two rejected requests,
   independently of actual dispatch count. In this run it released with zero attempts.
   Request and execution accounting were accurate; the opportunity ended without
   evidence. Release is a designed bounded fallback, not successful reproduction.
2. After release, the runner's pre-edit reproduction restriction no longer applies.
   The model could inspect and edit. It made 32 reads/searches but observed no original
   call, then assumed a directory was being treated as a file.
3. The submitted patch changes the successful lookup branch in `ast_from_file`.
   The saved public failure instead supplies a nonexistent initializer path with
   `source=True`; `NoSourceFile` preserves that value and `file_build` still fails.
   The trace and source support this path-specific explanation of the wrong patch.
4. At the cost horizon, only edit/check/finish remained in succession. The planned
   new regression test and actual caller check were omitted. The registered suite
   passed on the wrong patch, demonstrating that this PASS did not establish the
   original requirement under the observed conditions.
5. Finish admits unverified delivery when no case is pending or refuted and the
   required checks pass. It correctly retained the unmet original obligation.
   Recording the gap prevented a verified label; it did not repair the candidate.

## Interpretation and decision

The implemented changes separated error reporting, evidence accounting and financial
admission. None guarantees that a generated action repairs the named invalid field
or tests the causal hypothesis it relies on. Funding restored a tool-call shape and
retained submission, while request correction and original-path diagnosis failed.

The first full-25K incomplete response consumed USD 0.121066500 before any action,
which reduced headroom. It cannot explain the quote recurrence by itself: the next
two model responses were completed calls and the retry acknowledged the quote error.
The late completion restriction explains unavailable follow-up actions at that point,
not why earlier affordable opportunities were unused. No claim is made that more
money, a different model or a different inspection policy would have fixed the task.

The result narrows the next investigation from generic feedback loss to translating
a recognized contract error into changed executable arguments. A smaller request
construction interface or a field-specific correction path are candidates, not adopted
interventions. Whether either improves live reproduction remains untested. Existing
replay, uncertainty, private-boundary and cost protections remain in place.
