# Target-specific observations recover the declared failure in two saved probes

Date: 2026-10-24. Authorized local operator experiment, official=false,
claim-ineligible. Two programs on one development-exposed task; no fresh solver.

## Problem, hypothesis and decision

The [frozen caller diagnostic](2026-10-24-run.md) reached the original caller and
reproduced F0010 in both requests, but neither observation matched the declared
failure JSON. Its control emitted C0114/W0611, which the model's summarizer labeled
`other_error`; the declaration required `ok`. This matters because an irrelevant
clean-lint requirement can prevent original-failure acquisition even after a valid
caller execution, consuming the limited reproduction opportunity.

The leading explanation was an overbroad authored oracle. The smallest change was
to observe the reported fatal code specifically, while retaining other diagnostics
and refusing incomplete execution. Source, fixture or environment drift could also
alter the outcome, so the new execution was audited against actual prior calls.
Healthy comparable calls that still failed the newly declared JSON would weaken
the proposed correction; no predicate tuning or retries were allowed after dispatch.

The result supports that limited correction. Exact host JSON equality and completion
semantics remain. Generic model guidance is implemented, but its effect on fresh
model behavior is unmeasured. No new state machine, tool or task-specific host rule
was introduced.

to the fixed unused-import fixtures: they should produce diagnostics even without
F0010. It is not a generic classifier for every valid pylint invocation.
