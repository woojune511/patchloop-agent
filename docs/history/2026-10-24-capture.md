## Why this problem

The [preceding repair run](2026-10-24-repair-live.md) executed a valid request but
did not acquire its original failure. The model supplied `args=["src/project"]`
to an adapter that expanded `*args`, so pylint received a string instead of one
list argument. It then searched the returned Run object for diagnostics that
pylint had printed on stdout. Both base and candidate looked like the desired
result, while neither established the declared failure. Completion correctly
retained unverified delivery. These two construction errors blocked the first
required evidence stage; expanding acquisition or completion budgets would not
fix that observation.

Hypothesis: correcting both argument shape and the consumed observation channel
is necessary to distinguish the reported missing-init failure from its normal
control. Either correction alone sufficing, or an unhealthy call/capture would
weaken this account. The smallest diagnostic is a fixed public fixture and
predicate on the unchanged base, without asking a model to repair anything.

## Implemented change

Fresh invocation v3 / tool contract v52 exposes native Python calling syntax:

```python
target = observed_target(input_paths=[root], environment_keys=[])
call = target(["src/project"], do_exit=False)
# Inspect call.value, stdout, stderr, outcome, capture_status, exception, exit_code.
record_observation(actual_value)
```

The host binds inspectable signatures before calling, records raw arguments and
bound parameter names, and restores Python streams in finally. Each result has
a call ID and separate stdout/stderr. Capture shares 4,096 UTF-8 bytes across at
most four calls; the report is bounded to 10,000 bytes within the existing process
output allowance. Fixed host indentation is compacted to preserve the existing
8,000-character observer allowance, separately from model-authored source.

Truncation, replaced streams, deferred execution and unexpected exceptions leave
comparison unavailable. SystemExit, including nonzero exit codes, can be an
observed outcome. Intended exceptions require exact declared exception classes;
allowing Exception does not allow every subclass. The host also checks capture
health when reading a report. Empty capture alone cannot prove absence of a bug;
the authored predicate must check that the expected diagnostic channel completed.

Output, exception, exit code and bound parameter names are excluded from input
identity; raw arguments, selected inputs, environment and exception policy remain
bound. Thus repaired output can differ without looking like changed input. The
frozen JSON comparator and original-failure/current-candidate completion rule are
unchanged. Old v1/v2 observer bytes and replay APIs remain exact. Historical v2
grading is explicitly pinned to its old channel instead of the moving default.

Signature binding is not semantic type checking: both a string and list can bind
to pylint's `args`. Python stream capture does not cover native fd writes,
subprocess output or streams saved before the call, and is not an attestation.
The model still chooses the appropriate caller, arguments and observation.

## Decision and remaining question

Keep the native calling adapter and explicit diagnostic capture: both corrections
were necessary in this selected public fixture. Preserve original acquisition as
the completion prerequisite; desired JSON from a wrong observation must not
substitute for it. No further acquisition budget or completion gate was added.

This supports a local construction mechanism, not general input validation,
model uptake, repair gain or independent acceptance. All four cells are
operator-authored and share one exposed task/environment. A future separately
authorized model experiment must first show faithful original-call acquisition,
then test a repair hypothesis on the same frozen case and assess actual acceptance.
All previous paid allocations remain closed.
