## Question and decision

The [prior pilot](2026-10-25-original-feedback-live.md) exhausted two 25,000-token
responses before any tool execution. The [first-action audit](2026-10-25-first-action-analysis.md)
left first-action formulation and output allocation unresolved. The user selected
a single controlled configuration change: retain the `run_probe` recommendation,
raise the output ceiling to 40,000, and keep the other conditions, USD 1.20 cap
and one fresh solve unchanged.

This run produced a valid first probe, acquired the declared original failure,
and made three edits. Every edit received a comparable automatic original replay;
all three retained F0010. The first two replay results reached subsequent model
inputs, and the final edit explicitly revised its hypothesis after the failure.
No public regression, submission or independent evaluation occurred. The run
stopped when remaining money could not satisfy the completion reservation.

The output ceiling permitted one later response longer than 25,000 tokens, but
did not produce a repair. The first response used only 19,265 tokens, so its
success cannot establish that the larger ceiling solved first-action exhaustion.
Keep the runtime and general defaults unchanged. The next unresolved question is
how extended inspection, expensive repair generation and the retained correction
reserve interact with a still-failing original case. This record does not authorize
another run or imply that raising the cap would yield a correct repair.

## Why the run stopped with unused money

The terminal message is `completion cost reservation cannot fit the remaining cap`.
The unchanged recovery policy retained one unused correction at the requested
output ceiling. Its reserve rose from USD 0.157500000 at 25K to USD 0.225000000
at 40K, a USD 0.067500000 increase. Reservations are not billed expenditure.

At termination, USD 0.330274650 remained. Subtracting the correction reserve left
USD 0.105274650 for ordinary calls. Each conservative minimum costs USD 0.045576000,
so two calls were fundable. The still-failing `needs_mutation` state required three
minimum calls, totaling USD 0.136728000. That reservation was short by
USD 0.031453350. Physical limits still allowed nine model calls, 66 actions and
one edit, but the monetary completion condition did not.

The previous edit had been admitted with two minimum successful successors
reserved. A further unsuccessful repair returned to a state requiring three
calls. Thus successful-successor reservation and a funded protocol correction
did not ensure another failed-repair cycle would fit. The larger output ceiling
enabled a longer edit response and tied up more reserve under the same total cap.
This is an observed budget tradeoff, not evidence that releasing that reserve or
adding the small shortfall would have produced a correct repair.
