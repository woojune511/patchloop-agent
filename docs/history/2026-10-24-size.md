# Separate authored and observer source limits

Date: 2026-10-24. Local implementation and deterministic validation only;
official=false, claim-ineligible. No provider calls, containers or evaluator runs.

## Problem and decision

The [closed pilot](2026-10-24-request-live.md) rejected two original probes before
dispatch. Authored source was only 2,807 and 2,475 characters, but the host added
6,003 characters plus Python string escaping. The combined 8,000-character cap
left 1,997 serialized characters for the model. Actual source shortening still
failed. This admission defect prevented even attempting original reproduction;
model request wording or a larger acquisition allowance would not fix it.

Separate ownership of the budgets. Preserve the model's advertised allowance and
bound the host's instrumentation independently; derive a finite serialized bound
instead of assuming source escaping never expands. This is a known host contract
defect, not an agent-quality comparison. Two saved public requests provide the
smallest diagnostic: with their arguments fixed, admission should change without
changing the observer or generated execution bytes.

## Implementation

- Model source: 1–8,000 characters, at most 32,000 valid UTF-8 bytes. Helper and
  original requests use the same gateway limit; 8,001 characters remains a source
  field error before dispatch.
- Host observer including fixed headers: at most 8,000 characters / 32,000 bytes,
  excluding the serialized model source. Overflow is a host observer error.
- Composed execution: at most 88,002 characters / 112,002 bytes. Python `repr`
  needs up to ten ASCII characters per input code point plus two quotes. The
  sandbox launcher and standalone input reader consume this generated program.
- Shared Python limits live in `patchloop/probe_limits.py`; a focused test binds
  the standalone reader's byte limit to the host constant. Probe profile v3
  records the limits; tool contract v50 identifies the changed admission policy.
- Existing observer text, wrapper construction bytes, authored/execution hashes,
  action/input recovery and completion rules retain their meaning. CPU, time,
  output, filesystem, network and thread/process isolation limits are unchanged.

The low-level sandbox consumes host-composed source; the registered gateway
remains responsible for the smaller model allowance. Enlarging only one of these
checks would leave either the preflight or container input rejecting valid source.
Existing run/profile identities cannot be resumed as if this were the old runtime.

## Interpretation and remaining question

The deterministic admission evidence supports fixing the host budget split without
asking the model to further shorten these two requests. It establishes neither
successful original-caller execution nor semantic reproduction, acceptance or
general repair improvement. Helper API misuse seen in the pilot is a separate
problem. Live acquisition and actual Docker execution remain untested here;
all previous paid allocations remain closed. A future authorized pilot must use
fresh runtime/profile identities and first assess original-caller acquisition.
