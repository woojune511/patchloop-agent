## Question and boundary

The [public-source audit](2026-10-16-host-closure.md) found that a plan replacement
dropped an explicit host-volume obligation after a literal search miss. This
connector makes the already designed one-pair experiment executable; it supplies
no new diagnosis, task-specific reminder, source location, test, repair hint or
completion rule to either solver. No result here measures model uptake or correct
OpenSandbox repair.

`diagnostics/host_plan_checkpoint.py` restores independent copies of the settled
prefix through sequence 74, before prepared input 75, with the empty candidate,
original task, initial plan and native continuation intact. The historical full
system prompt is the A baseline on every request. B changes exactly the frozen
plan-replacement sentence. `host_plan_execution.py` verifies the complete first
requests after undoing that sentence and normalizing only the displayed actual
remaining solver seconds. Later delivery must invert to the same branch's ordinary
assembly; different model-authored trajectories remain allowed.

No core runtime changes were necessary. A scoped continuation verifier accounts
for the permitted system sentence when validating an inherited A segment in B.
It verifies original CAS bytes first and still checks task, seed and native
call/output prefixes. New segment seeds use the frozen arm-specific prompt.
An early synthetic rehearsal exposed this bridge requirement: changing the final
request alone broke seed identity at a handoff or B's first request. Those failed
local receipts remain under `C:/pt/hostplantry01` and `C:/pt/hostplantry02`;
`hostplantry03` records the intermediate successful pair. No model response,
treatment wording, rubric, cap or experimental condition was tuned.

## Execution and review contracts

- O1-A then O1-B, once each. USD 5.50 per row / USD 11 total, no transfers;
  ten new generations and ten new input counts per row / twenty each total.
  Historical USD 0.1582615 is recorded separately, not reopened as new funds.
- Fresh single-use count for the final dispatched payload, input at most 60,000,
  full 25,000 output reservation. The tenth matching dispatch is allowed;
  no smaller output ceiling, count retry, paid compaction or protocol correction.
- Thirty new tool actions and four accepted edits per row. Parallel reads and
  automatic rechecks each consume actions. Existing four-file / 1,000-line scope,
  source inspection, protected completion, plan-null and 3,000-character rules stay.
- Solver 1,697 seconds including restoration and preparation; public E/U/R review
  120 seconds, terminal public program 60, isolated evaluation 330. Each phase is
  clamped by the 2,400-second row and 4,800-second invocation deadlines. Actual
  displayed clocks are clamped, never falsified to obtain parity.
- Ordinary behavioral/resource failure closes its row and permits the remaining
  predeclared row. Count, usage, transport, integrity, execution or cleanup
  uncertainty stops the invocation. There is no retry, resume, replacement or
  result-driven adjustment.

`host_plan_review.py` seals E/U/R with public input, action, plan and final-source
citations before either terminal result. Only substantive accepted replacements
are U observations: null and unchanged-plan receipts are not extra replacements.
No replacement is NOT_EXERCISED; ambiguous evidence is NOT_OBSERVABLE; an earlier
unsupported narrowing remains FAIL after recovery. R permits equivalent code and
can be NOT_ASSESSABLE. U is not a requirement for actual repair success.

The frozen six primary public observations determine the behavioral part of P;
the two supplementary cases are descriptive. A fresh required regression on the
nonempty submitted diff is also necessary. Ordinary public FAIL may proceed to
the existing isolated evaluator. Stop/timeout cannot manufacture a submission.
No public terminal program, prior diagnostic outcome, private evaluator result or
other branch's result enters a solver request. Repair success requires E/R/P/I
and safety PASS, with bounded pair interpretation and no automatic adoption.

The later human reviewer receives `<row>/public-review-ready.json`, containing the
public packet reference and phase deadline, and publishes one complete
`<row>/public-grade.json` within that deadline. The packet's schema and
`validate_grade()` specify per-replacement input/event citations and final-source
hash/line citations. This is a bounded public semantic review, not a paid judge
or a claim of blinded scoring. Expired grades cannot be sealed or retried.
