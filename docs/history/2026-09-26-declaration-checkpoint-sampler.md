# Frozen first post-search declaration comparison

Date: 2026-09-26. Implemented and locally validated; live comparison NOT_RUN.

## Problem and hypothesis

The preceding optional gateway expanded adjacent declaration documentation in a
fresh run, but its offline search replay did not retain the original model checkpoint.
That could not isolate the next decision from an already formed interpretation.
The new diagnostic asks whether additional public source changes that immediate
question/action while the original first plan and native continuation remain fixed.
It does not revisit the causal limits of the earlier first-interpretation audit.

## Change

`declaration_checkpoint` verifies the source journal, envelope, public task, count/
dispatch identity, prepared source and encrypted continuation. It admits only the
first post-search decision after one successful initial search batch at the same
runtime. New diagnostic journals retain the exact prefix; inherited dispatch/usage
is labeled historical. Only recorded public searches are replayed. The ordinary
gateway/context/native builders recompute source-dependent state for A and B.

A must match the saved canonical context and request. B uses the existing generic
declaration/doc rule. It preserves plan, notes, budgets, task/diff/checks, prompt,
schema, call ordering and opaque continuation. Source bodies, fingerprints and their
derived projection change together; no hand-edited extra condition is supplied.
CAS key ordering is normalized to the same saved representation in both arms; exact
request identity does not mean an original HTTP wire capture exists.

`declaration_sampler` freezes the requests and delegates four independent decisions
in A1/B1/B2/A2 order to the existing counted, bounded one-response collector. Each
pair reserves full output capacity. All current uncertainty stops and zero retries
are retained. Source budgets are identical context, and a separate new ledger would
own actual spending. No selected tool, candidate, Docker or evaluator executes.

## Result and next question

Local evidence verifies reconstruction on synthetic and historical public records,
invariant continuation/plan, corruption/admission failures, independent response
collection and crash/uncertainty behavior. Test receipts, timings, source hashes and
the historical prepared comparison are recorded in the external packets below.
Core runtime remains `4d2fc8ba`; no default/tool-schema/planning changes were made.

The prepared four-response comparison is unexecuted. Its proposed cap is not a new
paid allocation. Actual model questions, eventual edits and acceptance are unmeasured.
If a later sample chooses a read, this diagnostic does not observe the resulting edit.
A repeated public-decision difference would support considering a separate rollout,
not declaring an improvement or automatically changing search defaults.
