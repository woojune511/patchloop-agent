Full success requires **D/U/P/I and safety PASS**. Merely mentioning the table,
making a plan, taking more actions, or recognizing a bad case is not success.
U uses the same semantic rubric as I1: conditional qualification counts; there
is no required wording, parser name, file, response field or simple reversion.
A correct patch without observable evidence-to-revision-to-action linkage is
U `NOT_OBSERVABLE`. Explicitly retaining the contradicted keyword premise, or
submitting the unchanged seed as sufficient, is U FAIL. Silence, reads alone or
a resource cutoff do not establish refusal to revise.

**Seal U and public event citations before both terminal assessments.** Only
an actual submission permits the frozen public oracle, followed by the isolated
evaluation. Normal public behavioral failure can still receive that one isolated
assessment; infrastructure/setup/receipt uncertainty stops it. A stop/cutoff is
not converted into submission. Assessment results never re-enter the solver.

## Question and competing explanations

I1 received all four public observations but used the successful issue example
and required-check PASS to close its keyword-based plan. The current position
failures appeared inside raw stdout strings. The narrow question is whether a
lossless four-case comparison display can support observable revision and a
correct final repair while the initial plan and completion advice stay fixed.

The display explanation predicts that making expected/base/current positions
directly comparable can lead to a different repair decision. Alternative
explanations remain: the model may retain its old hypothesis, prioritize the
exact issue example over derived controls, or follow the completion advice even
with a table. A faithful exposure followed by unchanged submission would show
the table is insufficient in this row. A revised hypothesis followed by a wrong
patch separates observable uptake from successful implementation. Time exhaustion
can censor the chain and is reported separately.

## Exact display intervention

Add only `operator_public_observation.case_comparison` to the first operator
packet. It is a JSON table with an ordered `columns` array and four ordered
`rows` arrays, appearing before `cases` under the existing canonical JSON order.
The columns are fixed:

`case_id`, `expectation_basis`, `expected_position`, `base_observed_position`,
`current_observed_position`, `base_position_preserved`, `current_position_preserved`.

For human review, the location columns are:

| Case | Original expected position | Base output position | Current output position | Expectation source |
| --- | --- | --- | --- | --- |
| `type_opening` | opening | item | opening | Original public issue |
| `type_item` | item | item | opening | Derived public position control |
| `plain_opening` | opening | item | item | Derived public position control |
| `plain_item` | item | item | item | Derived public position control |

The actual table copies the complete existing `expectation_basis` strings,
including the derived-control qualification, and the saved boolean observations.
Every value comes from the original case declarations or their existing
base/submitted stdout records. Source line/case mappings are frozen in the
static parity artifact. No expectation is strengthened or inferred from private
evaluation. No row is omitted, sorted by failure or highlighted as more important.

All original packet fields, program, both full receipts, stdout/stderr,
comment/AST results, setup flags, provenance notices and diff hashes remain
unchanged. The raw execution `passed` is not changed into a behavioral FAIL.
No aggregate verdict, new regression label, repair hint, location, extra
instruction or requirement to announce a hypothesis change is added. The new
packet is 25,211 bytes versus 24,554 before: **657 extra bytes of display data**.
This tests a table plus the unchanged raw evidence, not replacement that drops
diagnostic details. It also changes redundancy and token length; those effects
cannot be separated from the table's visibility in this minimal design.

## Stopping and interpretation

Stop before paid dispatch on source/receipt identity, table-cell fidelity,
first-input or non-treatment parity uncertainty. Stop on count, transport,
billing, continuation, private-boundary, infrastructure or cleanup uncertainty.
No retry, resume, model substitution, automatic Docker start or image pull/build.
An incomplete/malformed response receives no correction call. Apply the fixed
operation-specific caps and all phase/overall time limits.

No result-based wording, row, expectation, grading, seed, model or threshold
change; no additional sample or use of leftover budget. Preserve I2 even when
unexposed, unobservable, cut off or failed. Do not replace it with another row.

I1 is a historical single control and I2 a single new continuation, not a fresh,
randomized or replicated A/B. Even if I1 fails and I2 passes, sampling variation,
time and the increased explicitness/redundancy remain alternative explanations.
Success establishes local feasibility under this display, not a causal effect
size, spontaneous diagnostic selection, fresh-solve gain or general quality.
U PASS without P/I PASS does not justify adoption. A complete-chain PASS may
justify a separately chosen independent question, never automatic baseline
adoption. A negative/unobservable result closes this design without retuning.
